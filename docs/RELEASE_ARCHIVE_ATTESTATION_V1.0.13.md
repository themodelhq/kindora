# RELEASE ARCHIVE ATTESTATION — KINDORA v1.0.13

This file exists in THREE copies by design:

1. **In-archive copy** (`docs/RELEASE_ARCHIVE_ATTESTATION_V1.0.13.md` inside
   `KINDORA_v1.0.13_SECURITY_COMPLETE.zip`) — everything up to the MARKER.
   It intentionally carries NO byte-size or checksum figures for the archive
   itself: the archive's own hash and byte totals are self-referential (the
   archive cannot contain figures that depend on the copy of this file
   inside it) and any embedded values would be stale by construction.
2. **Post-packaging record** — the section after the MARKER, appended to the
   git-tracked copy immediately after the final archive was built and
   verified, with the ACTUAL measured values. That copy is authoritative.
3. **Top-level deliverable** `KINDORA_v1.0.13_RELEASE_ATTESTATION.md` (next
   to the ZIP in `download/`) — the complete post-packaging attestation for
   auditors who hold only the release artifacts.

The four evidence classes are kept SEPARATE throughout:

| Evidence class | What it covers | Where the actual values live |
|---|---|---|
| Nested backup checksums | `backups/KINDORA_v1.0.12_BASELINE_BACKUP.tar.gz` (the pristine v1.0.12 release tree pinned to `git rev 3bf94f0`, built by `scripts/v113_phase0_backup.sh`) and `backups/KINDORA_v1.0.13_FINAL_BACKUP.tar.gz` (the post-release source snapshot, built by `scripts/v113_final_backup.sh`) — each with its per-file SHA-256 manifest (`*_MANIFEST.sha256`) and its external archive-checksum sidecar (`*.tar.gz.sha256`) | the sidecars themselves (inside the archive) + the post-packaging record |
